# Caustica
<!-- impeccable:product-schema 1 -->

## Platform
web

## Stack
The implementation plan fixes TypeScript/Node24 for the CLI and semantic HTML/CSS/browser ESM for the owned checkout. SQLite persists orders. No hosted deployment is required.

## Users
Developers checking an AI-written repair and judges reproducing the bounded checkout demonstration.

## Product Purpose
Verify a repair against frozen requirements, demonstrate that an independent coupon fault is detectable, and reject changed-contract or different-build evidence.

## Operating Context
Local CLI, Kane in real Chrome, one Codex repair adapter, one owned checkout and an evidence-derived HTML report. User authorized continuation of PLAN.md.

## Capabilities and Constraints
One product: Caustica Field Notes, 10,000 cents, quantity one. SAVE10 deducts 1,000 cents. Orders persist across refresh. App-only repair candidates require their own healthy/control pair. Labels are Verified for this contract and control, Requirement failed, Evidence rejected, and Run inconclusive. No production correctness or remote attestation claim.

## Evidence on Hand
PLAN.md specifies the acceptance behavior and proof chain. Live evidence is still pending; reports must never manufacture a pass.

## Product Principles
- Bind evidence to actual served bytes and frozen requirements.
- Separate an independent control from a seeded source regression.
- Preserve raw artifacts and classify unknown failures as inconclusive.
- Make checkout amounts, submission status and persisted history clear.
